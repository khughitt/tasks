# Periodic Tasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a task carry a cadence (`every: 30d`) so that closing it anchors the next
cycle and the tracker surfaces it again when that cycle elapses, with no scheduler.

**Architecture:** Two frontmatter fields, `every` and `last_done`, plus a new `src/periodic.rs`
holding the interval type and the dueness arithmetic. Nothing rewrites a record on a timer:
`due` and `is_due` are computed at read time from the anchor and the interval, and the read
commands capture `now` once and thread it. The completion transition stamps the anchor and
appends an occurrence note; `transition` gains one allowance (`Done -> Doing` for a record
with a cadence) and one refusal (re-closing a record that is already done and recurs).

**Tech Stack:** Rust 2024, clap 4 (derive + `clap_complete`), `time` 0.3, `serde`/`serde_json`,
`assert_cmd` + `tempfile` for the end-to-end suite.

**Spec:** `docs/specs/2026-09-09-periodic-design.md` — read it alongside this plan; every task
cites the section it implements.

## Global Constraints

- JSON output is the contract. `--pretty` is for humans. Never change a JSON shape beyond what
  this plan specifies.
- Fail early with a typed error (`src/error.rs`). No silent fallbacks, no defensive defaults.
- Pretty output is ASCII only. No emoji, no box-drawing, no `↻`, no em dash.
- Conventional commits. **No AI-attribution trailers or footers** in any commit message.
- **This crate has no `[lib]` target.** Unit tests run with `cargo test --bin tasks <filter>`;
  `cargo test --lib` fails with "no library targets". Integration tests run with
  `cargo test --test cli <filter>`, and **cargo accepts only one positional filter** — run a
  second invocation rather than listing two names.
- Never edit the repository's own `tasks/*.md` by hand; the binary is the only writer. Test
  fixtures write into a `tempfile` project, which is not this repo, and hand-writing a record
  there is how several existing tests reach states no command produces.
- Gate before every commit: `just check` (`cargo fmt --check`, `cargo clippy --all-targets --
  -D warnings`, `tasks check`). Run `just gate` (adds `cargo test`) before each task's commit.
- After any CLI change, `cargo install --path .` so the `tasks` binary used by the session
  protocol is the code under test.
- **Close the step task in the same commit as its code**, per `AGENTS.md`. Each task's commit
  step shows this; find the id with `tasks tree tasks-5caeae --pretty`.
- Interval values are `<n>d` or `<n>w`, `n` a positive whole number with no leading zero,
  `1d` = 24 hours, `1w` = `7d`, `n` in days at most **36500**.
- Every new user-facing refusal is `Error::Validation` (JSON `error.kind` is `"validation"`),
  except `park` on a closed record, which keeps the existing `Error::InvalidTransition`
  (`"invalid_transition"`).

use crate::error::{Error, Result};
use std::fmt;
use time::{Duration, OffsetDateTime};

/// The largest interval accepted, in days. A product limit, not a representability
/// argument (spec §3.1): a century is a typo, and a stated number beats a platform
/// quirk. Representability is `add`'s job, and it is checked separately.
pub const MAX_DAYS: u32 = 36500;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum Unit {
    Day,
    Week,
}

impl Unit {
    fn suffix(self) -> char {
        match self {
            Unit::Day => 'd',
            Unit::Week => 'w',
        }
    }

    fn days(self) -> u32 {
        match self {
            Unit::Day => 1,
            Unit::Week => 7,
        }
    }
}

/// A recurrence interval: a positive whole number of days or weeks (spec §3.1). The unit
/// is kept so `2w` round-trips as `2w` rather than `14d`.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Interval {
    count: u32,
    unit: Unit,
}

fn bad(value: &str, detail: &str) -> Error {
    Error::Validation(format!("bad interval {value:?}: {detail}"))
}

impl Interval {
    pub fn parse(value: &str) -> Result<Interval> {
        let (digits, unit) = match value.strip_suffix('d') {
            Some(digits) => (digits, Unit::Day),
            None => match value.strip_suffix('w') {
                Some(digits) => (digits, Unit::Week),
                None => {
                    return Err(bad(
                        value,
                        "expected a count followed by d or w, such as 30d or 2w",
                    ));
                }
            },
        };
        if digits.is_empty() || !digits.bytes().all(|byte| byte.is_ascii_digit()) {
            return Err(bad(value, "the count must be a whole number"));
        }
        // A leading zero would not round-trip: `030d` and `30d` are the same interval but
        // two spellings, and the record must serialize back to what it parsed.
        if digits.len() > 1 && digits.starts_with('0') {
            return Err(bad(value, "the count must not have a leading zero"));
        }
        let count: u32 = digits
            .parse()
            .map_err(|_| bad(value, &format!("the count must be at most {MAX_DAYS}")))?;
        if count == 0 {
            return Err(bad(value, "the count must be greater than zero"));
        }
        let days = count
            .checked_mul(unit.days())
            .ok_or_else(|| bad(value, &format!("the count must be at most {MAX_DAYS} days")))?;
        if days > MAX_DAYS {
            return Err(bad(
                value,
                &format!("{days} days is longer than the {MAX_DAYS} day limit"),
            ));
        }
        Ok(Interval { count, unit })
    }

    pub fn days(self) -> i64 {
        i64::from(self.count) * i64::from(self.unit.days())
    }
}

impl fmt::Display for Interval {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{}{}", self.count, self.unit.suffix())
    }
}

/// `Task` derives `Serialize`, and an interval is one scalar in that shape, not a struct:
/// it serializes as the string it round-trips through, the way `TaskId` does.
impl serde::Serialize for Interval {
    fn serialize<S: serde::Serializer>(&self, s: S) -> std::result::Result<S::Ok, S::Error> {
        s.serialize_str(&self.to_string())
    }
}

/// The checked addition `validate_task` and `due` (Task 5) share. `None` means the sum
/// falls outside the representable range, which `validate_task` refuses (spec §3.1).
pub fn add(anchor: OffsetDateTime, every: Interval) -> Option<OffsetDateTime> {
    anchor.checked_add(Duration::days(every.days()))
}
```

/// Writes `last_done: <stamp>` into a task record, inserting the line if it is absent and
/// replacing it if it is not. Fixture-only: it reaches states the CLI produces later, or
/// (in Task 3) does not produce at all.
fn seed_anchor(dir: &std::path::Path, id: &str, stamp: &str) {
    let path = dir.join(format!("tasks/{id}.md"));
    let text = std::fs::read_to_string(&path).unwrap();
    let seeded = if text.contains("\nlast_done: ") {
        text.lines()
            .map(|line| {
                if line.starts_with("last_done: ") {
                    format!("last_done: {stamp}")
                } else {
                    line.to_string()
                }
            })
            .collect::<Vec<_>>()
            .join("\n")
            + "\n"
    } else {
        text.replace("updated: ", &format!("last_done: {stamp}\nupdated: "))
    };
    std::fs::write(&path, seeded).unwrap();
}
```

fn an_editor_save_cannot_set_or_move_the_anchor() {

    seed_anchor(&sci, &id, "2026-01-02T03:04:05Z");

    // Moving a live anchor is refused: the schedule may only move by a completion.
    let move_it = editor_script(

        "sed -i 's/^last_done: .*/last_done: 2020-01-01T00:00:00Z/' \"$1\"",
    );
    let out = env
        .cmd(&sci)
        .env("EDITOR", &move_it)
        .args(["edit", &id])
        .output()
        .unwrap();
    assert_eq!(out.status.code(), Some(1));
    assert_eq!(env.read(&sci, &format!("tasks/{id}.md")), before);

    // Changing the cadence alone is ordinary work, and keeps the anchor (spec §3.2).
    let recadence = editor_script(&sci, "sed -i 's/^every: 30d$/every: 7d/' \"$1\"");
    env.cmd(&sci)

/// The order `list --periodic` prints in (periodic design §5.2): unanchored due-now first,
/// then anchored records by due date ascending, then everything with no pending

pub fn sort_periodic(tasks: &mut [Task], now: OffsetDateTime) {
    fn key(task: &Task, now: OffsetDateTime) -> (u8, Option<OffsetDateTime>) {
        match (
            crate::periodic::due(task),
            crate::periodic::is_due(task, now),
        ) {
            (None, true) => (0, None),
            (Some(due), _) => (1, Some(due)),
            (None, false) => (2, None),

    }

        key(a, now)
            .cmp(&key(b, now))
            .then_with(|| a.id.cmp(&b.id))
    });

/// spec §4.7: `is_ready` excludes any task with children, so a cadence on a goal could
/// never fire. Refuse it at the write rather than leave a silent dead end. Scans only when
/// a cadence is actually set, which is rare.
pub fn validate_periodic(project: &Project, registry: &Registry, task: &Task) -> Result<()> {
    if task.every.is_none() {
        return Ok(());
    }
    let all = project.scan()?;
    let kids = children(&all, &task.id, registry);
    if !kids.is_empty() {
        return Err(Error::Validation(format!(
            "{} has children ({}) and cannot be a recurrence; a task with children is a \
             goal, and a goal is never ready",
            task.id,
            kids.iter()
                .map(|kid| kid.id.to_string())
                .collect::<Vec<_>>()
                .join(", ")
        )));
    }
    Ok(())
}
