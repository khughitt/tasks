Every project's pre-commit hook ends its check command with `tasks check`, and a clean run prints `{"errors":[],"warnings":[]}` on every commit. Nothing parses that stdout (every caller chains it with `&&`; only the exit status matters), so a `-q/--quiet` flag that prints nothing on stdout when both lists are empty and is otherwise identical lets the hooks go silent on a clean commit while still printing warnings, which exit 0 and would be lost if stdout were discarded. JSON shape unchanged; the default remains verbose. Test both modes; document in README and skills/tasks/SKILL.md; reinstall the binary.
