Observed friction (mindful v6, 2026-09-02): four pending sub-projects (SP51-SP54) existed only as a table in an umbrella design doc; the tracker showed 32 done and 1 todo, so nothing in tasks ready or prime surfaced that the roadmap had four large items outstanding. A reader of the tracker alone could not see what was next. Proposal to evaluate: invert the current convention. Today the flow is spec -> plan -> one task per plan step; tasks are downstream leaves. Instead, tasks are where goals are set and tracked first, at whatever granularity is known (an epic-sized todo with a body is fine), and specs/plans are optional attachments fleshed out as we push on each edge. Dependency graph (tasks dep, tasks graph) and priority then drive what to pursue next, including which design to write. Scope for this task: write the design (docs/specs/), covering at least: (1) an explicit notion of a large/roadmap-level task that can have child tasks (split via dep, or a parent field) and shows as pending rather than as an idea; (2) what prime/ready should show so roadmap-level pending work is visible without polluting the actionable list; (3) how the skill's session protocol and the superpowers brainstorming/writing-plans hooks change (tasks first, then optional --spec/--plan attachment); (4) whether check should warn when a design doc names sub-projects that have no task. Then split into implementation tasks.
