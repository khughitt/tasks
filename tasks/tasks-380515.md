Today a long title (plus its tags and @worktree suffix) in a --pretty table (`list`, `ready`,
`prime` sections, `parked`, `tree`) runs past the terminal edge; the terminal soft-wraps it to
column 0 and the next line no longer lines up under the table's columns.

Wrap within the last column instead. The renderer (`grid_text`/`table` in src/output.rs)
already leaves the last cell unpadded; it wraps that cell at word boundaries to the width left
after the fixed columns, and every continuation line is indented to the column's start so the
fixed columns stay clear.

Decisions:
- Width comes from the terminal stdout is attached to (TIOCGWINSZ via libc); `COLUMNS`
  overrides it. When stdout is not a TTY and `COLUMNS` is unset, nothing wraps: piped output
  keeps one line per row, so `grep` and `head` keep working. (Rejected: always wrapping to a
  default 80 — it breaks line-oriented pipes.)
- Only the last column wraps; fixed columns (id, priority, size, complexity, process, status,
  dates) never do. A word longer than the available width is hard-split.
- Below a floor (about 20 visible columns left for the title), the table renders unwrapped
  rather than as a one-word-per-line column.
- Width counts visible characters, as the column widths already do; pad first, paint last
  still holds, and each continuation line carries the cell's style.
- Tree output wraps under the node's own indentation.

Done when: a unit test renders a table at a fixed width and shows continuation lines aligned
under the title column; an end-to-end test shows `COLUMNS=60 tasks list --pretty` wraps and
piped output without COLUMNS does not; JSON output is unchanged.
