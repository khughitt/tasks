Today a long title (plus tags and owner or claim suffixes) in a --pretty task table
(`list`, `ready`, `prime` sections, `parked`, `tree`) runs past the terminal edge.
The terminal soft-wraps it to column 0, so the next line no longer aligns with the table.

Wrap the trailing title and suffix text within the width left after fixed columns. In
`src/output.rs`, `table` renders task rows, `parked_table` renders parked rows, and
`tree_text` adds node indentation. `grid_text` renders the separate `projects` grid
and is outside this task. Indent each continuation line to the title's start, including
a tree node's indentation.

Decisions:
- Width comes from the terminal attached to stdout (TIOCGWINSZ via libc); `COLUMNS`
  overrides it. When stdout is not a TTY and `COLUMNS` is unset, nothing wraps, so
  piped output keeps one line per row. A default width of 80 would break line-oriented
  pipes.
- Only the trailing title and suffix segment wraps; fixed columns never do. Hard-split
  a word longer than the available width.
- If fewer than 20 columns remain for the title, leave the row unwrapped rather than
  rendering a one-word-per-line column.
- Measure visible text before applying ANSI styles. Preserve the styles on suffix text
  across continuation lines. Tree rows wrap under their own indentation.

Done when: a unit test renders a task row at a fixed width and shows continuation
lines aligned under the title; an end-to-end test shows `COLUMNS=80 tasks list --pretty`
wraps, while piped output without `COLUMNS` and a 60-column row with the width floor
stay unwrapped; JSON output is unchanged.
