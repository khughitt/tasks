Problem: `tasks show --pretty` reads as a wall of text. Sections (frontmatter, body, ## Notes, Process, # parked, # parent/children) are barely set apart, and fields that `list` colors are plain here: created/updated/started dates get no Style::Date recency color, size/complexity/process are unpainted, and note timestamps, note owners, and the indented provenance JSON lines all render at body weight. Screenshot attached (a mind6 task with several parks).

Current code: roles are already centralized in src/style.rs (Style::Status/Priority/Date/Chrome/...), but each view maps fields to roles itself. show goes through output.rs::paint_frontmatter/paint_field (only id, parent, depends, owner, tags, status, priority) and show_text, whose doc comment deliberately leaves keys, body, and notes verbatim so the output stays copy-pasteable. That decision is what this task revisits.

Want:
- One field-to-role mapping (e.g. a per-field style function in style.rs or a small render module) used by list, ready, prime, parked, and show, so a field looks the same in every view. A field added later gets its role in one place.
- show: dates painted by recency; size/complexity/process styled as list styles them; section headings set apart (Emphasis or similar) with consistent spacing; note lines with a dim timestamp and owner and the text at normal weight; provenance continuations and the parked session line dimmed; keys dimmer than values.
- Copy-paste and the plain output stay intact: no added characters, only ANSI; --color=never and JSON unchanged.

Design questions for the spec: how much structure to add beyond color (rule lines, heading glyphs) without breaking copy-paste; whether show keeps the raw-frontmatter layout or switches to an aligned key/value block; whether wrapped note continuations should indent under the text.

Done: show and list paint the same field identically via one mapping; a pretty-output test covers each styled role in show; the user has judged a rendered sample.
