Why: a park recorded on one host survives the record's close elsewhere (claims and parks are host-local). tasks-b9b10e's probe shows prime's parked section listing the closed task while list --parked hides it unless a status filter is given (list.rs::list_parked filters is_open; parked::rows does not). Three reports (tasks-6b2867, tasks-2c7979, tasks-912279) read prime's row as live work that nothing can clear, though a repeated `tasks done <id>` (or `tasks drop <id> "<why>"` for a dropped record) clears it and changes only updated. prime's stale-claim warning on a closed non-recurring record likewise suggests `tasks start --force`, which refuses invalid_transition there; done is what clears it.

Done: prime leaves a park whose record is done or dropped out of parked and instead warns once per entry, naming the status and the clearing command (done or drop by status), as it already warns about stale claims; its stale-claim hint names the same clearing command when the record is closed. list --parked is unchanged; shelved parks stay listed for cleanup. Tests in tests/cli.rs with two XDG_STATE_HOME stores. This changes prime's output contents, not its JSON shape; the choice of prime over list --parked is the recommendation recorded in docs/notes/2026-10-06-record-continuity-brief.md.
